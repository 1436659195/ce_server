# Codex Session 接续与失败通知

2026-11-27：修复带图片的 Worker Session 接续失败。

## 原因与接续行为

`thread/resume` 默认回传历史轮次，包括图片数据。walle 的一次历史响应为
9,787,898 字节，超过 CE 的 8,000,000 字节协议消息上限，后续 TXT 工单在开始
模型轮次之前失败。CE 接续只需 Session ID 与权限信息，不使用返回的历史轮次。

能力检查现在检测安装的 Codex 是否支持 `excludeTurns: true`，并随兼容性结果
缓存。支持时接续仅返回元数据，不修改、清空或替换模型历史，也不新建 Session
或卷宗。旧协议缺少此可选能力时沿用原有恢复方式，不以版本号拒绝；旧协议返回
超大历史时仍会明确失败，不自动新建会话重做。8 MB 接收限制保持不变。

## 失败通知

Worker 启动或执行失败会原子保存失败状态及内部 `unable` 消息，经 Router 整理
后送达聊天。对外只使用经过归类的诊断，不直接复制原始错误中的账号配置。
通知绑定任务版本和运行 ID；任务停止、重新排队、换轮次或权限失效后取消旧通知。
有效失败通知不能被 Router 静默省略，且会替换尚未发送的受理话。

自动任务在通知整理或网络重试期间保持 `delivery_pending`，送达后再结算为
`needs_attention`；用户暂停、撤销和权限检查继续生效。

## 验证

回归覆盖大图片历史、能力缓存、旧协议、消息上限、通知脱敏、过期通知、Router
省略/取消、自动任务离线重试与用户暂停。使用真实 walle Session 的隔离副本和
安装的 Codex 验证：原 Session ID 成功恢复，历史轮次不回传，响应为 27,249 字节；
副本中的模型历史完整，原始 Session 未改变，验证期间未启动模型任务。
