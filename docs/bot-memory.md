# 数字人记忆：存储、披露与生命周期

## 内容边界

- 长期：稳定偏好、持久事实、长期约定；`core=true` 仅用于整个 Bot 都适用的长期规则。
- 中期：影响后续多轮、但有时间或阶段限制的偏好。无明确结束条件时默认七天；有明确时间按时间，有任务/卷宗阶段按 `end`。
- 一次性要求留在任务记录；方法与踩坑留在经验库。拿不准持续性不能默认塞进中期。
- 用户/Bot/渠道由宿主绑定。项目是宿主核实的工作目录，任务/卷宗使用本 Bot 的真实 ID；情境条件保留在 `appliesTo`，不能冒充已核实的结构条件。

记忆保存 `topic/kind/tier/core/scope/appliesTo/startsAt/expiresAt/end`，来源消息 ID 与必要原话、版本、状态和替代/覆盖关系。原文使用已有 `chat_read` 追溯，不额外复制整段聊天。

## 获取与写入

Router 对“记住、改掉、忘掉”的明确委托使用 `memory_write`，收到真实 ID/版本回执才确认。自然交流由已有后台记忆 Agent 提炼；同批可以提炼多个独立主题。后台继续检查显式保存以外的主题；只有来源、主题、正文、范围、类型和生效/结束条件都一致才自动去重。同一消息中不同时间段的要求分别保留。

后台输入是完整当前消息批次、消息时间和宿主时区、近期交流、关联任务摘要及相关旧记忆。新证据只能来自本批未撤回的用户原话；助手推测、引用资料不能自动当成用户事实。

模型查询并判断相关旧记忆，在一次提炼中产生结构化操作；程序验证来源、身份、作用范围、版本、时间与关系，然后原子提交整个批次：

- `duplicate`：同一含义，保留现有规则，必要时追加独立来源；不会增加采用次数或延长原期限。
- `supersedes`：永久同范围改变，旧记录退出生效，新记录保留关系；新规则必须已生效且没有截止时间或阶段结束条件。用户明确长期化可以由中期变长期，中期不能永久取代长期；有期限的要求使用 `overrides`，避免到期后丢失默认规则。
- `overrides`：临时或窄范围例外。基础规则仍保存；覆盖到期后自动恢复。语义情境交 Router 判断，不能仅凭命中关键词就当条件已满足。
- `related`：已检查且可共存。不能把含糊的新要求强行解释成替代。

同主题所有未失效记录都必须有冲突检查结果，包括其他项目、被暂时压下、尚未开始生效的记录。`memory_search(topic=...)` 专用于这类完整检查，不受当前项目/任务范围限制，但仍严格隔离用户/Bot/渠道；按 `nextOffset` 翻页。

同一次提交区分已有记录与本批新增记录：每条规则仍须检查已有记录；本批新增记录的 ID 尚未返回，由程序验证它们的时间窗口或结构范围确实不重叠，因此“这周简短、下周详细”可以一次原子保存。区间按左闭右开处理，相邻边界允许接续。范围与时间均重叠、又无法明确关系的批内规则拒绝整批保存，不猜测语义兼容。多条分时覆盖可引用同一旧规则，覆盖关系不会修改旧规则的版本；失败不保存任何新记录，也不占用请求编号。

写入要求 `expectedRevision`，冲突目标也带版本。版本变化则补查后重试；失败不保存半个批次。替代、覆盖、撤销、删除还会核对来源消息顺序（含最新补充来源），旧后台消息不能覆盖较新的用户要求。请求编号幂等，不允许同编号提交不同内容。后台未成功提交（包括模型直接结束）标为 failed，与成功提交 `changes=[]` 区分。

## 披露

固定流程，不因记忆库小就全部注入：

1. 排除撤销、过期、被替代以及范围不符的记录。
2. 仅明确标记的全局长期核心规则常驻。
3. 用当前消息、近期对话和关联任务构造有界查询，向量语义检索与 SQLite FTS5 关键词检索合并排序。关键词只检索本轮候选，不再预截前 200 条，最终结果统一限量/分页，避免失效、其他范围或档位的记录挤掉有效命中。
4. 无条件覆盖关系在程序中解析。覆盖记录继承基础规则的相关性与核心常驻资格，避免新旧规则都掉出上下文；情境覆盖保留条件及关系供 Router 判断。
5. 长期最多 30 条、中期最多 10 条，合计摘要最多约 6000 UTF-16 字符；不凑满，溢出显式计数，可继续查询。

向量请求结束后才读取正文、有效性和版本，后续筛选排序同步完成；等待期间的删除、覆盖和到期都按最新状态处理，不能返回旧正文并标注新版本。

语义分数使用余弦相似度（当前门槛 0.5），关键词分数使用全文排名。合并为 `0.7 × semantic + 0.3 × keyword`，低于语义门槛的语义分量不计。没有额外的逐轮生成式模型调用；分数只用于召回，不代表规则真伪或条件已满足。

具体记忆放在每轮输入的 `memories.long/mid`，系统提示词只说明如何使用。本轮快照是权威；库版本或披露范围/集合变化会重建 Router 会话，避免旧内容驻留。派活时 Router 把适用规则写进 `executionGuidance` 给 Worker。

`memoryIds` 是 Router 明确采用的记录。宿主核实 ID/版本、有效状态与本次决策的范围。新任务不继承上一个任务的范围；复用卷宗只允许该卷宗规则，不因此取得旧任务专属规则。披露/查询次数与实际采用次数分别记录，幂等记账，不影响记忆有效期。

## 查询与更新

- `memory_search`：语义/关键词、主题、档位、范围、创建时间区间（毫秒或带时区 ISO）、条数、偏移和版本校验。普通查询返回当前有效关系；`topic` 检查模式和 `history=true` 可见未生效/失效记录，结果标明 `effective`。翻页沿用筛选、`revision`、`cursor`，偏移使用 `nextOffset`；索引或有效期变化导致结果集合、顺序或分数变化时拒绝续页，从第一页重查。`revision` 仍是写入使用的内容版本，`cursor` 只校验查询结果指纹，不保存正文快照。
- `memory_read`：读取完整记忆、来源消息 ID；`history=true` 分页查版本摘要，`version` 读取指定版本。旧版本只作证据，不能当当前规矩。
- `memory_write`：明确保存/变更/撤销/彻底删除，以及 `end(kind,id)` 结束用户明确关闭阶段的中期偏好。
- 原始交流仍用 `chat_search/chat_recent/chat_read`，不建立第二套聊天原文入口。没有查到不证明用户从未说过。

“这次详细讲”只影响本任务；“这周详细讲”形成中期覆盖；“以后详细讲”才是长期修改。命中次数不再自动晋升长期，轮次数也不再使中期失效。

## 遗忘与历史

时间到期由后台巡检处理；任务阶段自动结束以 `completed + review.approved` 为准，停止、失败、待验收均不视为最终结束。卷宗尚无自动关闭状态，用户明确结束讨论时通过 `end(kind=case,id)` 关闭对应阶段记忆。阶段结束保存来源序号截止线，阻止旧消息延迟提炼复活；延迟到达的旧结束事件也不能关闭后来重新开始的规则。无法核实阶段结束就不擅自认定。

普通遗忘使用 revoke，保留可追溯历史并立即退出披露；长期未采用可标记待复核，不自动删除。Owner 可暂停/恢复有效记录，但不能直接复活已撤销或到期记录。

彻底删除使用 purge：清除该记录正文、历史快照、全文/向量索引和相关缓存，保留不含正文的最小墓碑与幂等回执，防止旧任务重放恢复。旧版共享来源的冗余 context 副本同时清除；其他独立记忆的有效原话不删除。原聊天记录属于聊天保留策略，不会随删除记忆一起被删除。

来源消息撤回时清空本地消息正文并撤销该来源支持的记忆；如果还有独立有效来源，则切换到剩余来源继续保留。

旧记录保守迁移：保留历史，不猜测为全局核心；标记待复核并按需检索。不会自动修正线上旧偏好的含义，也不会批量删除旧记录。

## Embedding 配置

无新增运行时依赖，兼容标准 OpenAI embeddings HTTP 接口，包括本地服务：

```sh
CE_MEMORY_EMBEDDING_URL=http://127.0.0.1:11434/v1/embeddings
CE_MEMORY_EMBEDDING_MODEL=your-embedding-model
# 服务要求鉴权时设置 CE_MEMORY_EMBEDDING_API_KEY
```

未显式配置 URL 且存在 `OPENAI_API_KEY` 时，使用 `OPENAI_BASE_URL`（默认 `https://api.openai.com/v1`）下的 `/embeddings`，默认模型 `text-embedding-3-small`。端点、密钥不进入模型上下文；记忆文本和查询会发送给配置的 Embedding 服务。

向量在后台分批建立，按端点/模型及内容哈希缓存。查询向量最多等待两秒，并有有界缓存；失败时回退关键词，`retrieval.warning` 明确报告未配置、故障或索引尚未就绪，不假装语义召回完整。索引失败退避一分钟，正文变化/撤销会清除旧向量；迟到的索引结果重新核对当前记录，不能恢复已删除数据。

## 验证场景

1. 明确记住两个独立偏好，核实两条来源与真实回执；重复提交不重复创建。
2. 用“别啰嗦”保存，用“简短回答”查询，配置 Embedding 后应可语义召回。
3. 全局简短规则加一条本周详细覆盖；时间内生效，到期恢复。
4. 同主题不同项目规则只在对应范围披露，冲突检查可以完整查询它们。
5. 停止/恢复任务不遗忘，完成验收或明确结束讨论后结束阶段偏好。
6. 撤回主来源但保留另一独立来源，记忆继续有效；全部来源撤回后退出披露。
7. 明确彻底删除后查不到正文和旧快照，重放旧保存请求不恢复。
8. Embedding 故障仍能关键词补查，并能看到降级提示。
