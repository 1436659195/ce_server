# 数字人经验机制

## 写入

普通任务的完成报告保留在任务历史，不再自动等同于经验。Worker 在 `work_finish` 中可提交一个聚焦主题的 `lesson` 草稿；Router 能看到草稿，对照结果和检查决定是否通过 `router_decide.acceptLesson` 保存。没有批准、被返工或失效的结果不发布草稿。

用户明确要求总结经验时，Router 可以根据现有材料调用 `experience_save`，或者让原 Worker 补充。保存工具返回真实编号和版本后才可声称已入库。每条经验包含主题、适用条件、结构化环境范围、坑点、推荐步骤、验证方法，以及可选正文和附件引用。建议更新已知经验编号；主题、对象、目标、适用说明和环境范围完全相同的新增请求返回已有条目回执，不会静默制造重复。相同名称、不同对象或条件不能被吞并；含义上的同一主题由 Router 搜索后选择原编号更新。重复回执不代表新修改已保存。

## 检索

Router 根据当前用户原话、明确的长期约定、当前任务目标形成检索条件。例如「服务对齐」结合已保存的约定，展开为 CE 版本核对、远程构建、替换和重启。

`experience_search` 仅查询当前 Bot。项目、服务、操作系统等明确冲突的经验被排除，条件未知的保留并提醒核实。当前机器的操作系统不代表远程目标操作系统，不能擅自套用。

精确版本 `scope.version` 与当前已知版本比较：完整数字版本可忽略 `v` 前缀，其他构建号仅在统一大小写、去除首尾空白后完全相等才匹配；已知不符则排除，当前版本未知则保留并提示核实。同时填写精确版本和范围时，两个条件都必须满足。版本范围按完整数字版本（如 `>=1.2.0 <2.0.0`、`^1.2.3`、`~1.2.3`）检查；未知版本、非数字提交号或不支持的简写保留候选并提示核实，不能据此误判不适用。

不超过 20 条适用经验时提供全部候选的简短目录，由现有 Router 理解含义、选择最多 3 条派工。更多经验用 SQLite FTS5/BM25 字词召回并分页，每页最多 20 条。中文分词与连续二字组合、英文标准化词参与索引；主题/适用条件高于长正文。Router 可更换关键词继续查询，不要求凑满 3 条。没有新增向量库或独立模型服务。

语义判断由 Router 完成：直接解决当前问题、预防当前流程中的坑、仅有对象重合，是不同程度的相关；检索阶段不能用展示次数替代这种判断。

## 使用和记账

Router 在派工时选择 `experienceRefs`（经验编号、版本），并写明本次使用的具体执行指导。Worker 用 `work_read_experience` 读取派发版本及其材料；版本发布后，正在执行的工单引用不悄悄切换。

展示、阅读、采用、成功分别记录。`work_finish.experienceUsage` 声明采用、调整后采用、跳过或发现问题，列出具体步骤和结果。模型不能靠填一个未派发的编号增加使用次数。每个任务/经验只计一次采用，返工不叠加；Router 批准交付并存在实际检查结果后才记成功。Worker 的声明是采用依据，验收不是经验效果的因果证明。

## 更新和状态

更新需要编号、预期版本、修改说明与本次消息/任务/交付来源。系统校验归属和版本后保存不可变历史，冲突时要求重读，不覆盖其他更新。同一主题优先完善原条目，不同适用环境可以拆开。新增建议没有经过实际验证时保留未验证状态。

同一任务先报告旧经验失败、同时提交修复草稿时，失败仍会立即把旧经验升版为待复核。验收修复草稿可以衔接这一次由本任务自动产生的状态版本；系统核对失败回执、任务来源和连续版本，不放宽对其他内容或人工状态更新的冲突保护。修复通过实际检查后发布有效新版本；缺少检查时保存改法但仍保持待复核。旧版本的失败记录不因此变成成功。

经验可标待复核、停用、恢复；历史版本保留供审计和已派发任务读取。跨 Bot 的来源和材料不能作为当前经验的授权。附件保留实际快照编号、版本、哈希，读取前核实，不接受模型提供的任意路径。

设置界面中主人主动停用经验也走版本记录，来源为已认证的主人管理操作（`ownerControl`），不伪造一条聊天消息或借用旧工单。这个宿主入口只修改状态，不允许凭主人身份把未经验证的内容标为已验证；模型工具不能提交这种来源。

## 工具和边界

| 入口 | 作用 |
| --- | --- |
| Router `experience_search` | 关键词、目标环境范围、条数和偏移分页查询 |
| Router `experience_read` | 按编号、版本和章节读取，可查历史和已停用经验 |
| Router `experience_save` | 本轮用户委托的结构化保存/更新，返回编号和版本 |
| Router `experience_state` | 带预期版本停用、复核或恢复 |
| Worker `work_read_experience` | 只读取本工单已派发的版本及关联材料 |
| Worker `work_finish` | 可附一条 `lesson` 草稿和最多三条 `experienceUsage` |
| Router `router_decide.acceptLesson` | 验收当前交付时发布草稿并返回保存回执 |

每次派工最多新增三条经验引用；后续补充可以保留此前已授予的版本。经验查询与普通历史查询使用独立预算：Router 每轮最多八次经验查询，单次返回最多 16000 字符，总计最多 32000 字符；普通查询仍为四次、单次 4000、总计 8000 字符。长正文、步骤和历史用分页读取，Worker 草稿与采用说明合计最多 16000 字符，更多材料用关联附件。

全文排序权重为主题（含对象和目标）8、适用条件6、坑点4、步骤3、正文1。中文采用词语和连续二字组合，英文先标准化再按词匹配；这是字词召回。是否真正适合任务由 Router 根据目录和详情判断，不把字词分数等同于语义正确，也不把 Worker 自报采用等同于效果的因果证明。

## 旧数据

旧 `uses` 是混合展示/读取次数，迁移后仅保留为历史曝光，不成为真实采用或成功次数。旧任务报告保留但退出经验推荐；可识别的专门复盘/手写条目保留为经验，保存来源与原文。迁移不调用模型、不替用户确认未经验证的内容。历史报告仍可通过任务查询找到。

## 验证

- 让数字人完成普通任务：不应出现新的普通「已完成」经验。
- 要求总结一个明确主题：应得到保存的编号/版本；重复补充应更新原主题。
- 让 Worker 提交经验草稿再返工：旧草稿不得提前进入有效经验。
- 检索、聊天和阅读详情不能增加采用次数。
- 派发后更新经验：原 Worker 仍能读派发时版本。
- 明确采用并验收后检查采用、成功记录；重复提交不能重复累加。
