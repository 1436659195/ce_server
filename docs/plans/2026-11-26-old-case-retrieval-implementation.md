# 旧卷宗检索漏召回：实施记录

日期：2026-11-26。针对原方案第二项“旧卷宗能搜更多了，但换个说法仍可能找不到”。已读原方案、第二项TXT/MD并通过CodeGraph核对现有代码。本次保护第一项未提交改动，在其基础上修改；未提交、部署或打包。

## 改了什么

以前主要靠文字包含找旧资料，还只能拿前5份。现在增加三种小而直接的补救：知道任务/成果ID时直接查所属卷宗；对已知重连说法补少量对应词；相似结果多时可以继续翻候选。改动仍在CE侧数字人宿主管理模块，影响提供给Agent的资料，不改模型引擎、session恢复策略或APP页面。

| 原五点方案 | 本次取舍及落地 |
| --- | --- |
| 明确关联优先 | case_search增加可选taskId、artifactId。不依赖文字分数，按真实账本定位卷宗；任务、成果及卷宗均检查Bot归属；同时给两个ID时必须指向同卷。无权或失效ID返回空，不偷偷退回关键词结果冒充精确定位。已有消息targetTaskId关联继续复用。 |
| 稳定搜索目录 | 复用第一项的实时、按卷宗聚合搜索字段，继续覆盖现名、旧名、对象、目标、摘要、任务和成果。不新增持久搜索表：当前没有需要双写的新数据，另建表会引入回填和同步成本。改名后立即可查，旧名仍保留；这不等于已建成全文索引。 |
| 先多找再筛 | 保留评分排序，内部保留最多30份，每次最多返回5份摘要；增加offset以继续看后面的结果。长摘要可能触发预算裁页，因此offset按实际收到的条数增加，而非固定加5，避免跳过尚未交付的候选。明确ID直接定位，跳过截断问题。 |
| 受控换词重查 | 默认候选与显式搜索共用一小组重连术语：如重连、连接恢复、重新连接、reconnect及已核实的两种口语。扩展匹配低于完整字面匹配；没有把“网络问题”泛化为重连。工具说明引导在无结果时换核心词、结果拥挤时翻页，最多建议追加2次；整轮4次读取及内容预算仍由宿主硬限制，没有另造检索状态机。 |
| 必要时语义检索 | 暂不引入模型服务、向量库或依赖。当前明确关联、候选截断和已知用词缺口可用现有结构修补；任意同义句、含糊指代仍不能保证理解，应以真实样本评估后再决定。 |

业务代码只扩展现有 `ce-server-repo/src/cli/bot-runtime/{cases,store,service,router}.ts`。新增检索回归测试，并在原Worker生命周期测试中补工具链及长摘要分页场景。未扩大用户消息附件协议：当前消息只接收upload，故未保留不可达的“artifact消息附件”分支；成果引用通过已知真实artifactId查找。

## 怎么验证的

先新增失败测试，确认原实现不能召回已知换词、不能按成果ID查卷宗或继续候选；实现后通过。只读审查另外发现“长摘要裁页后固定加5会漏项”，已补集成复现再修复，并通过复核。

最终实际执行：

- **全部Bot测试323通过、0失败，27文件、1686断言，约23.71秒，退出0**。包含改说法、现名/旧名、成果文件名、精确ID及跨Bot隔离、候选截断/分页、长摘要不跳项、4次读取预算，以及原有归卷、Worker/session和第一项历史读取回归。
- **TypeScript检查通过，退出0**；`git diff --check`通过。
- 小样本机制对照：“掉线后再也进不去”及“reconnect”对“连接恢复异常”的评分从0变为0.75；完整同名文字仍为5；“reconnect”对“网络带宽测速”仍为0。分数只是排序依据，不是正确率。
- 相同名称的旧卷宗被前5份截掉时，后页可以找到；持真实任务/成果ID时可直接定位。内容预算会裁页的场景，继续读取不重复、不跳过记录。

## 剩余边界

本次是“小改补明确缺口”，不是完整语义理解。未覆盖的口语、简称和相似事项仍可能漏找或误召回；找到候选也不保证Agent必然选对。最多30份是有界候选窗口，整轮读取/内容预算也不保证一次看完30份。翻页没有跨请求快照，历史并发更新时排序可能变化。

显式搜索仍扫描本Bot的投影搜索字段；Router自动候选仍使用历史快照，这次没有推翻第一项架构或宣称所有开销固定。代码已验证，但运行中的服务没有被替换；正式使用还需对应版本运行与真实对话验收。本次无需修改原HTML设计文档。
