# History Reading Implementation Plan

**Goal:** 实施历史读取的五项优化，保留原搜索和任务状态语义。
**Architecture:** 单轮快照共用、按Bot+卷宗分组；SQLite条件/排序/限量查询用于日常刷新，历史搜索独立执行，表达式索引配合真实条件。不跨轮缓存。
**Tech Stack:** TypeScript / Bun / SQLite。

1. 新增查询回归：最近列表分页、旧活动任务保留、卷宗关联隔离、搜索与旧算法一致；先运行确认缺少查询接口失败。
2. cases.ts 单次分组；store.ts 新增按需查询与索引、数据库搜索，保留旧公共接口兼容调用者。
3. service.ts 刷新只读必要行，一次读取恢复记录与记忆；搜索结果一次按卷宗读取；Worker上下文收窄到当前卷宗。
4. 执行bot回归、类型检查、查询计划与合成数据前后对比，记录实际行数与边界。
5. 更新实施MD并导出附件。不提交、不部署、不打包APK、不恢复旧任务。
