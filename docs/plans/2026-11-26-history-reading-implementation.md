# 历史读取与重复扫描：实施记录

日期：2026-11-26。范围仅为原方案第一个问题的五点。已读取原MD、TXT及当前源码；后端存在.codegraph，先通过CodeGraph定位调用关系。目录确认后在共同父目录内实施。未提交、部署、打包APK或继续其他停止任务；原HTML无需变更，未重制。

## 实际修改

| 原方案五点 | 本次落地 |
| --- | --- |
| 1. 同轮读取一次共用 | 搜索结果的任务、成果各查询一次，所有结果共用；Worker上下文与附件目录共用同卷宗数据；刷新恢复记录一次读取。无跨轮持久缓存。 |
| 2. 按卷宗分组 | 以Bot+卷宗为键建立分组；候选评分和摘要从分组取资料，替代逐卷filter全历史。搜索数据库也先分组。 |
| 3. 数据库按需查询 | 刷新查询最近30任务及全部活跃任务、关联卷宗、最近30成果、各任务最近30输入、未知操作/执行；Worker只查本卷宗。最近列表支持limit/offset；保留既有插入顺序，非擅自改为更新时间排序。记忆/经验及失败记忆任务也收窄到所需条件和条数。 |
| 4. 配置真实索引 | tasks/artifacts按Bot+卷宗，tasks/runs/tool_operations按Bot+状态，task_inputs按任务，以及失败记忆任务/记忆状态查询的表达式索引。已有Bot索引服务最近列表，ID主键服务关联卷宗。启动时幂等建索引，保留旧JSON正文。 |
| 5. 刷新与历史搜索分开 | view不调用历史搜索，也不全读tasks/cases/artifacts/runs/operations/memories/experiences再截取。显式case_search独立查完整历史可搜索字段，评分后只解析最终候选正文，再一次查询这些卷宗的任务和成果。 |

业务修改4文件：后端 `src/cli/bot-runtime/{cases,router,service,store}.ts`。新增查询回归测试与可复跑对比脚本。开始时后端git工作区干净；未重置或覆盖其他既有修改，前端只更新本实施记录。

- 新增测试先因查询接口不存在失败，接入刷新后曾因仍全量读取失败，再实现到通过。覆盖分页无重复、旧等待任务不丢、插入顺序、Bot隔离、旧名/任务/成果/Unicode搜索、无结果查询、重开数据库和辅助快照限量。
- 最终Bot功能回归（排除单列的CLI进程测试）：**311通过、0失败，1622个断言，25文件**。覆盖归卷、Router、Worker生命周期、目录确认、附件、记忆和session来源等已有场景。
- CLI进程测试单独运行：**7通过、1失败**。失败在真实Node子进程3秒内未写出启动标记（`test/bot-cli.test.ts:90`）；本次未修改该测试及其旧CLI执行模块。未证明它的具体根因，不把此失败算通过，也未扩大到无关CLI修复。
- TypeScript检查和 `git diff --check` 通过；只读独立代码审查已复核，无剩余关键问题。未做真实APP/模型/生产账本联调。
- 查询计划确认最近列表用tasks_bot、活动任务用tasks_state、卷宗成果用artifacts_case、输入用inputs_task。搜索聚合关联原曾退回逐卷SCAN；实测发现后补明确TEXT类型，使SQLite采用自动覆盖索引，新增计划回归防止再次出现该退化。

## 边界及尚未完成的验证

五点已在上述路径落地，**不等于整个系统所有历史读取都已变成固定开销**。Router每轮自动候选准备仍读取本Bot历史快照，已分组且单轮共用；显式搜索仍扫描本Bot完整投影字段，尚无全文/语义索引。未改原方案其他独立问题，也未建立独立搜索表或改归卷规则。

为不漏状态，全部活跃任务、全部待审记忆、必要未知执行记录仍会返回；这些数量大时响应仍会增长。Worker本卷宗附件目录也随本卷宗历史增长。offset分页在静态历史上验证无重复；并发插入时不保证跨页快照一致，未提供游标接口或新增APP历史页面。
