# 数字人待办与事件

Router通过一个`automation`工具管理事件。宿主持久化检查时间和指标，只有到期、条件成立或监测连续失败需要告知时，才唤醒Router。条件未满足时不调用模型。

## 可用例子

- “明天下午3点提醒我开会。”：一次性`at`，具体时间存为带时区ISO。
- “每天早上8点查上海天气发给我。”：`cron: 0 8 * * *`，`timezone: Asia/Shanghai`。天气查询由触发后的Worker完成，依赖实际网络/数据来源。
- “每小时检查一次这个任务。”：`every`，有固定anchor，不因重启改变周期。
- “这个工单完成后检查成果。”：监听同一数字人的指定`task.completed`，任务通过Router验收后触发。
- “本机CPU超过90%持续3分钟提醒我，75%以下恢复，冷却30分钟。”：受控指标采集器定期检查、宿主状态机判断；无需让模型不断查询CPU。
- “有哪些待办？暂停天气提醒，改成9点，删除会议提醒。”：工具支持分页查询、详情、修改、暂停、恢复和删除。

缺少地点、时区或监测目标时，Router先查已有上下文，无法确定再询问。只有收到宿主`{saved:true}`回执才可确认建立成功。

## 执行与停止

事件固定绑定创建时的数字人、owner、私聊、源消息和权限/目录版本。触发是原委托的延续，拥有独立occurrence记录，不伪造用户聊天消息。

简单提醒由Router回复；需要专业工作时派Worker，结果仍经Router验收，必要时返工。普通提醒100字纯文本；本轮实际Worker文字结果500字以内可用Markdown；附件回复100字纯文本。

停止本次工单只取消当前occurrence，下一次周期保留。owner明确继续已停止工单时，按既有继续流程执行，脱离旧的已取消occurrence，不复活旧通知。暂停/删除事件会取消该事件当前运行和未发送结果；已发送消息或已完成的外部操作无法自动撤回。

自动事件轮可查看、暂停、删除自身事件；可以在原委托7天内创建最多3层的一次性后续检查。自动轮不能把自身改成无限周期或访问其他事件。owner聊天轮可管理自己的全部事件。

## 故障处理

- 事件定义、触发事实、每次合并的幂等回执与运行状态均存SQLite；任务接单和触发消费使用同一连接事务。
- 重启后未提交的Router触发可恢复；已有Worker工单继续关联原工单。结果未知时保留待核对，不自动重做副作用。
- 周期错过多次只保留最近一次；默认补执行窗口1小时，过期一次性事件保留待处理原因。
- 执行预算默认10分钟、最长30分钟。消息发送独立重试同一个outbox ID，不受执行预算到期影响；显式事件有效期仍在派工/发送前校验。
- 原消息撤回、owner/私聊/目录/权限变化或事件有效期结束时，原触发失效，相关检查和Worker停止。停用整个数字人保留事件定义，但不继续执行。
- 条件检查超时30秒，独立最多3个检查槽；连续采集失败会退避，第三次失败向Router提交监测异常通知，不能把采集失败当成指标正常。

## 当前边界

- 宿主服务必须在线，触发后的排队、查询和模型生成会增加实际到达延迟，不提供硬实时保证。
- 内置目标仅`host`；CPU为当前宿主采样利用率，磁盘为宿主进程当前工作目录所在文件系统的已用比例；GPU依赖可用的`nvidia-smi`，多GPU取最高利用率。其他挂载盘、AMD GPU和远程机器需另接采集器。
- 指标检查至少间隔30秒，支持持续阈值、恢复滞回和冷却。暂不提供磁盘I/O指标、任意脚本、任意webhook、日志stream和复杂多事件组合。
- 每数字人默认最多100个未完成/未删除事件；同一事件最多一个活动执行和一个合并待执行项。历史分页读取，日常巡检只查活动记录。
- 使用聊天工具即可管理；本次未增加独立日历页面。后台代码更新需要另行部署，APK无需新增权限。

## 开发验证

在`ce-server-repo`运行：

```sh
bun test test/bot-automation-*.test.ts
bun run typecheck
bun test
```

测试使用临时SQLite、可控时钟/样本和假的RuntimeClient协议端，不需要真实智能体参与；不会向真实用户创建通知。另有当前宿主CPU和磁盘collector的只读实测。真实模型对自然语言需求的解析质量尚需上线环境做单独验收。
